# Local autoplay recommendations

Status: accepted, 2026-10-16.

Autoplay is enabled by default for new and existing installations, with one persisted setting shared by Settings and Player. It is independent of automatic caption generation. No external recommendation service or model is used.

The shared heuristics module chooses only playable, unwatched videos, excluding the current item and items completed in this playback-service session. Prefer the next chronologically published item with the same show and inferred topic; then the next item in the show; then backfill an unwatched item from that show. Missing dates sort after dated items for continuation. Without a show continuation, rank shows using the last twenty actual played-video records, weighting recent records more strongly. Within the preferred show, favor an in-progress item, otherwise the oldest unwatched item. With no relevant history, use the newest unwatched video. Stable video-ID tie breaks make recommendations reproducible. Existing shared show/topic rules remain authoritative.

The Media3 service owns completion and handoff, so screen visibility does not govern continuation. A gate requires actual playing state before accepting an ended event, rejects paused, preview-only, idle, and error cases, and consumes a completion once. A posted handoff rechecks the active media ID, ended state, play intent, error, and persisted setting before changing playback. It persists final progress first, uses existing media metadata/caption construction, resumes incomplete progress, and starts completed-but-explicitly-unwatched items from zero. An exhausted library stops. It does not retry unavailable streams or start playback merely because the setting is enabled.

Player displays the proposed next title and a reason, with an explicit Play next now action available even when autoplay is off. Recommendations are independent of Library filters/sort. The service recomputes at completion to account for changes to watch state, history, or feed contents; it never prefetches private media or sends viewing history elsewhere. There is no countdown: the setting is the persistent opt-out and pause/stop suppresses continuation. Cast uses the existing shared Player and route handoff, but real receiver acceptance remains separate from local tests.

Media3 1.9.2 [RemoteCastPlayer source](https://github.com/androidx/media/blob/1.9.2/libraries/cast/src/main/java/androidx/media3/cast/RemoteCastPlayer.java) maps receiver idle to Player.STATE_IDLE rather than STATE_ENDED. For Cast, accept only a connected remote session whose receiver reports IDLE_REASON_FINISHED for the last known matching stream. Preserve outgoing progress when the receiver clears its idle timeline; cancellation, errors, a different stream, or disconnect must not advance. This adapter has fixture coverage; a physical Cast receiver check is still required.
